# Законы репозитория

Законы обязательны для всех — и для человека, и для ИИ, попавшего в репозиторий.

## Протокол приземления (для ИИ)

1. Прочитай README.md, затем MAP.md, затем INDEX.md.
2. Открой ТОЛЬКО нужный файл. Никогда не читай всё репозиторий целиком.
3. Чтобы изменить одно место кода, не нужно изучать всё остальное:
   цепочка README → MAP → INDEX → файл.
4. Изменил файл — обнови INDEX.md (и MAP.md, если файл новый).
5. Изменил код — запусти самотест: `cd tools && python -m tests.selftest`.
   Все проверки должны быть OK до коммита.

## Законы кода (tools/)

- Python 3. Сторонние библиотеки ЗАПРЕЩЕНЫ — только stdlib.
- Метод — кирпичик: ≤ 15 строк тела, одна ответственность.
- Сложное собирается из простого: core → доменные модули → пайплайны.
  «Ветвь кода»: сложный метод вызывает более простые, те — ещё более
  простые, до предела простоты.
- Каждый метод описан в tools/METHODS.md: имя | вход | выход | функция.
- Новый метод = сначала запись в METHODS.md, потом код.
- Файл ≤ 500 строк. Больше — дели на части (_part2 и т.д.).
- Имена: файлы и функции — snake_case, без кириллицы в именах файлов.
- Комментарии и docstring — на русском языке.
- Запуск скриптов — из папки tools/: `python -m pipeline.order_all` и т.п.

## Законы данных (data/)

- Только факты, извлечённые из файлов сборки. Мнения — в analysis/.
- Формат JSONL: одна строка = одна запись. Без вложенных строк-гигантов.
- Источник данных указывается в data/meta.json и в analysis-файлах.
- Данные не редактируются руками — только регенерируются инструментами
  или заменяются целиком новой версией.
- Перед запуском экстрактора (tools/extract/*) — закоммить текущее
  состояние: экстракторы перезаписывают data/.
- Лимит «500 строк» НЕ применяется к data/*.jsonl: их читают
  инструменты (METHODS.md), а ИИ смотрит их через отчёты пайплайнов
  (top_report, quest_order-выборки) или главами (data/chapters/).

## Законы анализа (analysis/)

- Каждое утверждение ссылается на файл из data/.
- Числа сверяются с данными, а не пишутся по памяти.
- Один файл = одна тема. Побольше 500 строк — дели.

## Законы плана (plan/)

- План — пошаговый: один шаг = одно конкретное действие в игре.
- У каждого файла плана: цель, предусловия, шаги, критерий готовности.
- План опирается на данные и анализ, а не на догадки.
- Нумерация: NN_название.md, NN — этап (совпадает с TRACKER.md).
- plan/auto/ — ГЕНЕРИРУЕМЫЕ чек-листы квестов. Руками менять можно
  ТОЛЬКО галочки `- [ ]` → `- [x]`. Любая другая правка будет стёрта
  генератором (он галочки сохраняет, остальное перезаписывает).
- plan/museum/ — ГЕНЕРИРУЕМЫЕ чек-листы предметов (цель «все предметы
  хотя бы по разу»). Правило галочек то же, что у plan/auto/.
- Два слоя: plan/auto/NN_*.md — точные чек-листы из данных;
  plan/NN_*.md — стратегия игры поверх чек-листа.

## Законы прогресса (progress/)

- Игрок отмечает выполненное в progress/TRACKER.md и галочками в
  plan/auto/*.md (квесты) и plan/museum/*.md (предметы).
- Счётчики — командами `python -m pipeline.progress_count` (квесты) и
  `python -m pipeline.museum_count` (предметы), из папки tools/.
- Статусы: [ ] не начато, [~] в работе, [x] сделано.
